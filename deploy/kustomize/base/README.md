# The portable Cairn base

One instance's portable resources and nothing a particular cluster needs
(P-62, I-08). Overlays add the cluster's storage class, the FalkorDB
component and the egress gateway; this directory names none of them.

The rendered form of this base is committed at
`../rendered/base.yaml` with a digest beside it, regenerated by
`make render` and diff-gated inside `make check` (P-61). Edit the
sources here, never the render.

## What an operator must supply

The base is deliberately not applyable as it stands, and both gaps are
the kind that should fail loudly rather than default quietly:

- **`instance_id`** in the ConfigMap is a placeholder. Every instance
  needs its own; two instances sharing one would let a backup bundle
  from either restore over the other, which I-41 refuses on exactly this
  value.
- **The `cairn-credentials` Secret** is referenced, not created —
  secrets are operator-supplied and never live in a rendered artefact
  (I-19). The mount is optional because the base disables the retrieval
  index and so reads nothing from it. An instance that enables the index
  without the Secret gets I-92's typed startup refusal naming the
  missing file.

Nothing reaches the instance until an operator says what may: ingress is
denied by the default-deny policy, and the Service is ClusterIP only
(I-12, I-13).

## First boot is a two-step, not an init container

`migrate` runs as an init container because it is idempotent.
`bootstrap` is not: it takes the exclusive data-directory lease and a
repeat exits 4 with `realm_exists`, so a bootstrap init container would
poison every later Pod restart.

Before the StatefulSet first starts — or with it scaled to zero — run a
one-off Pod on the same image, config and claim:

```sh
cairn bootstrap --realm <realm> --label <label>
```

Capture the one-time token from its output, then delete the Pod. The
kind acceptance harness performs exactly this sequence, so the
documented procedure is the tested one.

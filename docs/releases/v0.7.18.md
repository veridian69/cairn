# Cairn v0.7.18

`v0.7.18` (`drystane-cairn==0.7.18`) is a patch release on v0.7.17. The memory
MCP server can now tell clients its connector conventions, and a script checks
the self-built Redis and FalkorDB pins against upstream releases. Cairn's REST
and v1 MCP contracts, catalogue schema and Attic format are unchanged. The
memory MCP manifest gains one description per `scope` parameter, so its digest
changes. The FalkorDB runtime recipe and the Python graph clients are as in
v0.7.17. This release ships source and local build recipes, not container
images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags.

## Memory MCP server instructions

**Instructions on `initialize`.** A client connected to `/memory/v1/mcp` had to
be told the deployment's conventions by pasted text. Without them, a model
guessed the scope and was refused. The memory MCP server now returns the
connector conventions from `docs/operations/browser-connectors.md` as the MCP
`instructions` field of `initialize`, naming the realm configured in the new
optional setting:

```yaml
mcp:
  instructions_realm: <realm>
```

Leave it unset and the server sends no instructions, as before. The text is
guidance only: the server never fills in a scope from it, and every call still
supplies the arguments its tool requires. The guidance now covers every
mutating tool's idempotency key, not only `remember`'s.

**Scope hint.** Every memory tool's `scope` parameter carries a fixed
description saying that the server never fills in a scope and that its
instructions name the realm. The hint is static, so the manifest stays
independent of any deployment. It reaches clients that ignore server
instructions but show schema descriptions.

**Price.** Clients differ in whether they show server instructions to the
model, so the pasted text in the connector document remains the fallback.
Setting `mcp` needs v0.7.18: v0.7.17 rejects unknown configuration keys and
will not start with it. To roll back to v0.7.17, remove the `mcp` block from
the configuration before starting the older image.

## Runtime currency check

The image scan covers the Ubuntu packages only; Redis and the FalkorDB module
are compiled from source, so falling behind on them never fails a scan.
`scripts/check-runtime-currency` compares the pins in
`deploy/falkordb/build.sh` with upstream GitHub releases. It reports each
component as `current`, `behind-patch` (exit 1; for Redis it also names newer
patches whose notes say `SECURITY`) or `newer-line-available` (information
only). Any failure exits 2. `--container NAME` reads the pins from a running
runtime container's image labels instead, and `--status FILE` writes the result
as JSON for a scheduled job to report. It reads public release data without
credentials and never changes a pin: a pin change still goes through build,
scan, acceptance and rollout.

## Upgrade

Replace the Cairn and edge images with v0.7.18 builds. The catalogue schema is
unchanged, so `migrate` is a no-op, and FalkorDB need not be restarted. To send the instructions, add the `mcp` block above
in the same change that moves to the new image, and validate the configuration
with the new image's `check-config` before restarting Cairn.

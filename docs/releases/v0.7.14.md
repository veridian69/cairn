# Cairn v0.7.14

`v0.7.14` (`drystane-cairn==0.7.14`) renames Garden's binary, source module and
runtime identifiers from `a2a` to `garden`. Garden was already the product
name; the command, paths and wire names now match it. Cairn's REST, MCP and
memory contracts, catalogue schema and Attic format are unchanged.

The same release adds the browser-connector edge and per-client Cairn
credentials for the relay, described under
[Browser connectors and per-client identity](#browser-connectors-and-per-client-identity).

- The binary is `garden` (`garden start`, `garden chat`, `garden mcp`,
  `garden serve`, `garden host`, `garden connect`, `garden attend`,
  `garden doctor`). Its source lives in `garden/`, the Go module path is
  `github.com/veridian69/cairn/garden`, and the module gate is
  `make -C garden check` (root target `check-garden`). The overview moved from
  `docs/a2a.md` to [`docs/garden.md`](../garden.md).
- The default configuration and runtime directory is `~/.garden`; managed
  installations use `/var/lib/garden/.garden`. The JetStream stream is
  `GARDEN`, its NATS subjects are `garden.*`, and internal environment
  variables use the `GARDEN_` prefix.
- The guided installer installs `garden/bin/garden` for native mode and
  `/usr/local/bin/garden` in the Garden image. Generated adapter instructions
  and the MCP client examples name `garden connect` and `garden attend`.

**No migration.** A `garden` binary does not read state written by an `a2a`
binary: an existing `~/.a2a`, stream or managed Garden from an earlier release
is ignored rather than converted. Stop and remove an old Garden (`a2a stop`,
then delete `~/.a2a` and `~/.local/bin/a2a`, or remove the managed Garden with
the installer), install this release and re-enrol participants. Agent MCP
configurations that call `a2a` must be updated to `garden`.

Historical evidence, handoffs, plans and earlier release notes keep the `a2a`
name they were written with. This release ships source and local build recipes,
not container images.

## Browser connectors and per-client identity

**`cairn-edge`.** A new Go service that lets browser connectors (claude.ai,
ChatGPT) reach Cairn's memory MCP mount without holding a Cairn credential
themselves. It validates the Cloudflare Access assertion on each request (issuer, audience,
signature, expiry and the one allowed identity), refuses service-token logins,
and forwards the request as that inbound path's own workload principal. Each
route has its own credential file, so the audit chain shows which connector
acted. Nothing about the edge makes Cairn trust it: the principals are
ordinary Cairn principals with ordinary grants. Build the image with
`make image-edge VERSION=0.7.14 EDGE_IMAGE=cairn-edge:v0.7.14` (the local tag
pinned in `deploy/images.lock`) and add `deploy/compose/compose.edge.yaml` to a Compose
project. See [`docs/operations/cairn-edge.md`](../operations/cairn-edge.md),
[`docs/operations/browser-connectors.md`](../operations/browser-connectors.md)
and the edge section of
[`deploy/compose/README.md`](../../deploy/compose/README.md).

**Relay change: a Cairn credential is now required.** `cairn-mcp` sends the
Cairn bearer credential, in addition to the two Cloudflare Access credentials,
on every upstream request. It reads it from
`~/.config/cairn/cairn-credential` (`--cairn-credential-path`; mode `0600`, same
checks as the other two files) and refuses to start without it. Windows
`setup-windows.ps1` now prompts for it. Rotate it with the other two files,
then send one `SIGHUP` to the Unix HTTP service; a Windows relay runs over
STDIO and picks up new credentials only when Codex restarts. Each host gets its
own workload principal, so every memory operation carries that host's identity.

**Do not run `install-user` before the runbook says so.** `install-user`
restarts a running relay onto the new binary, which sends the Cairn credential
and expects a v0.7.14 upstream. It validates the credential file first and
stops with "Cairn credential is missing" before it builds or restarts anything,
so a missing file leaves the running relay untouched; a present file does not.
Upgrade a relay host only when its credential is in place and the upstream it
talks to is ready.

**Principal and credential issuance.** `scripts/cutover_principals.py` creates
the workload principals, their grants and their credentials against a named
instance, one credential file per `--label`; labels are required, with no
default inventory. Idempotency keys are deterministic, so
a rerun replays rather than duplicates; an existing credential file is kept
only if it authenticates, and a failed write leaves the old file intact.
`--reissue N` issues a new credential and replaces the local file. It does not
revoke the earlier one; after the replacement is loaded and verified, revoke
the superseded credential with `POST /v1/revoke-credential` (`grant-manage`).
The script is now part of `make check`'s type check.

`make check-cairn-mcp` (part of `make check`) runs the edge's tests with the
rest of `cairn-mcp`. No registry image is published for the edge either;
deploy from a local build.

## Migration tooling

**`cairn_migrate overlay`.** A new pure, offline step between `map` and
`apply` that applies a curation rulings file to a full migration plan and
writes a curated plan with its own manifest; `apply` and `verify` consume it
unchanged. Every input (full plan, base plan, covered plan, rulings) is
pinned by SHA-256. Base operations are carried byte for byte; graph episodes
the covered plan already holds are dropped and counted, and newer ones are
accepted unruled. Ruled Attic turns become curated facts that keep the turn's
store, legacy id and idempotency key; unruled turns and conversations are
rejected and counted. `--prior-plan` takes an already applied plan and
carries its operations byte for byte, so a later plan resumes them from the
same receipts and only the delta is applied; a rebuilt operation that differs
is counted as `prior_drifted`, not carried.

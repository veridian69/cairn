# Cairn v0.7.0-rc.2

`v0.7.0-rc.2` (`drystane-cairn==0.7.0rc2`) replaces the release-supplied
FalkorDB runtime with an operator-built local runtime while retaining the shared
Garden conversation service and guided native, Docker and Kubernetes installers
introduced in rc.1. It does not change the catalogue schema, Attic format or
versioned REST/MCP contract.

## Changes

- A reviewed Linux amd64 recipe builds FalkorDB 4.20.4 and Redis 8.6.3 from
  pinned sources on a digest-pinned Ubuntu 24.04 base. Compilation runs without
  network access and is capped at ten parallel jobs.
- The local export records the immutable image identity and archive checksum in
  `runtime.json`. Guided native and Docker semantic installations retain that
  descriptor and refuse registry fallback.
- A separate administrator tool transfers the verified archive to explicitly
  mapped containerd nodes. Guided Kubernetes retains the resulting node receipt,
  checks node UIDs and eligibility, and proves the exact cached digest with
  unprivileged `Never` probes before deploying FalkorDB.
- Cairn and Garden image handling is unchanged. FalkorDB node preparation does
  not grant the namespace installer host access or privileged Kubernetes access.
- Interrupted Kubernetes acceptance runs report failure and clean up their owned
  disposable cluster. Python subprocess, database, socket and HTTP resource
  ownership warnings remain fatal in the test suite.
- **Garden is not supported on macOS. Run Garden on Linux.** Cairn catalogue
  memory and Attic remain available through the documented macOS foreground and
  launchd paths; macOS semantic search remains disabled.

## Installation

Use a trusted checkout of this tag, Python 3.12–3.14 and uv 0.12.14, then run
`./cairn-install`. Follow the [installation guide](../install.md), the
[local FalkorDB build and node-staging procedure](../../deploy/falkordb/README.md)
and, when required, the [managed Garden guide](../operations/managed-garden.md).
Garden is a separate Go binary and is not part of the Cairn Python wheel.

New Linux native and Docker semantic installations require the retained
`runtime.json`. New semantic Kubernetes installations require the receipt made
after the same archive has been staged on every selected node. Retain the
accepted archive for recovery and restaging; rebuilding produces a different
local identity.

## Publication and acceptance boundary

This is a **Gitea-only** release candidate. Do not publish it to GitHub. The
release contains the recipe and staging tools, but no FalkorDB image archive,
source bundle or GHCR publication. The locally built database runtime is an
operator artefact and is not a Cairn release asset.

The local Ubuntu build passed authenticated graph/vector queries, save/restart
persistence, synthetic Graphiti integration and staging on two disposable
Kubernetes workers. Installer cache probes passed twice per worker, with
server-side affinity validation and graph queries using the exact local digest.
Trivy 0.70.0 reported zero HIGH/CRITICAL, five MEDIUM and four LOW package
findings for that build; this does not certify future rebuilds or provide a
complete vulnerability audit of compiled source dependencies. Revision-specific
source and package acceptance is recorded with the Gitea release.

Fresh hosted Intel and Apple Silicon macOS acceptance has not run for this
candidate. Prior macOS acceptance does not certify these new artefacts.

Remote semantic search, macOS 12 and an actual macOS logout/login cycle remain
unvalidated. An existing Garden conversation is not automatically a Cairn
memory record: Cairn scope, grants and evidence rules continue to apply
separately.

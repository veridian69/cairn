# Cairn v0.8.3

`v0.8.3` (`drystane-cairn==0.8.3`) is a patch release on v0.8.2. It upgrades
`apt` in the runtime image for a HIGH advisory, repairs semantic index damage
left by a host hard reset without a full rebuild, re-asks edge-deduplication
questions a combined answer left out, tightens Garden's checks on the files it
trusts, restarts every long-running container after a reboot, and reports
Cairn's own version in MCP `serverInfo`. The REST and MCP contracts, catalogue
schema and Attic format are unchanged; one optional configuration field,
`delivery.repair_cap`, is added. This release ships source and local build
recipes, not container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in
`deploy/images.lock` name local source-build tags.

## Runtime image: `apt` 3.0.4 for CVE-2026-109518

The `python:3.14.7-slim-trixie` base ships `apt` and `libapt-pkg7.0` 3.0.3.
Debian fixed CVE-2026-109518 (HIGH) in 3.0.4, and the image gate rejected the
v0.8.2 image from 5 November. Both packages join the runtime stage's
`--only-upgrade` list, as for earlier base-image fixes. Scanner thresholds and
image pins are unchanged. Other HIGH findings in the base image have no Debian
fix yet; the gate reports them and rejects only fixable ones, as before.

## Targeted repair of a torn semantic index

**What failed.** The deliverer retires an outbox row once projection returns,
but a host hard reset can still lose those last index writes. A fact left
partly projected fails the all-or-nothing coverage checks, so semantic recall
for its whole partition stays degraded until a full `rebuild-index`. A fact
lost entirely passes the checks and is silently missing from semantic search.

**What changed.** An audit derived from the coverage checks' own queries finds
torn and missing facts, and a repair enqueues a re-projection for each one the
outbox does not already cover; the normal deliverer does the rest. At startup
the delivery loop repairs up to `delivery.repair_cap` facts (default 50; 0
turns startup repair off). Semantic search reports degraded until that audit
finishes and every fact it found has projected. Above the cap nothing is
enqueued, `projection_repair_over_cap` is logged, and search stays degraded
until an operator runs the new uncapped `cairn repair-index [--dry-run]` with
Cairn stopped. It exits 4 with `status: partial` while work is still owed. New
safe log events are `projection_repair_enqueued`, `projection_repair_over_cap`,
`projection_repair_unrepairable` and `projection_repair_failed`. Automatic
repair with a cap, a CLI for the rest, and failing closed meanwhile follow
Operator's rulings of 21 October 2026. See
[semantic fact search](../operations/semantic-fact-search.md), "Targeted
repair".

**Price and bound.** Each start serves lexical-only recall for the seconds the
audit takes. Re-projection can call providers, normally answered from the
projection caches. The cap bounds what the server re-projects unattended.
Repair rows queue behind any failing rows at the head of the outbox, as new
ingests already do; that delays repair but fails closed. An indexed episode
that matches no catalogue fact cannot be repaired by row and is reported as
`projection_repair_unrepairable`; use `rebuild-index` for that.

## Edge deduplication re-asks omitted items

Graphiti edge resolution is batched, up to ten questions in one call, and
answers are matched by item number. An item the model left out got empty
duplicate and contradiction lists, so its edge was never deduplicated and could
not invalidate a fact it contradicts; a 1-based answer shifted every answer one
item along. Per Operator's ruling of 21 October 2026, each omitted item is now
re-asked on its own with Graphiti's un-batched call. When any item number is
out of range or repeated, or item 0 is missing, no answer in that batch is
trusted and every item is re-asked. A failed single call fails only its own
projection, which the outbox retries. The price is a few extra small-model
calls per full rebuild at the observed omission rate, and up to ten for a
misnumbered batch.

## Garden checks the files it trusts

`LoadHome` now opens the Garden home only when its parents are trusted and the
home is owned by the current user and not group- or other-writable, and reads
`garden.json` through that pinned directory. The profile, identity token and
host credential get the same ownership and permission checks, through one
non-following descriptor. A configured TLS CA must be an absolute, clean path to
a regular file owned by root or the current user, not group- or other-writable,
under trusted parents; `Connect` checks it before dialling. Refusals name no
path in the session's disconnect reason.

Exposure needed a non-default `$GARDEN_HOME`, profile or CA path writable by
another account. Homes and profiles written by the installer or import, and the
default `~/.garden` at 0700 or legacy 0755 with 0644 files, still pass.

## Every long-running container restarts always

The shipped Compose files and the installer's rendered Compose now use
`restart: always` for `cairn`, `falkordb`, `cairn-edge` and `garden`, and the
native installer starts its FalkorDB container the same way; one-shot init
containers keep `restart: "no"`. This brings back a container that was stopped
before a reboot or daemon restart, per Operator's request of 21 October 2026. A
deliberate `docker compose stop` now lasts only until the daemon next starts;
use `down` to keep an instance off across reboots. That includes disposable or
test instances.

## Smaller changes

- MCP `initialize` now reports Cairn's version as `serverInfo.version` on both
  served transports, rather than the MCP SDK's. The client-side
  `cairn-conversation` stdio bridge still reports the SDK version.
- The garden-server backup hook now says when Garden's runtime lease stayed
  busy: it exits 75 with "archive published; Garden's runtime lease stayed busy
  for 300 s, so snapshot `<id>` was kept", and a failed removal reports its own
  exit status. Both still fail the unit and alert through `OnFailure`. This
  closes the residual noted in the v0.8.2 notes.

## Upgrade

From v0.8.2, rebuild the image. To apply the restart policy to a running
Compose installation without redeploying, run
`docker update --restart always <container>` for each long-running container;
otherwise it applies when the Compose project is next re-rendered or
redeployed. Reinstall a garden-server hook to get the lease message. A Garden
home, profile or CA that another account can write is now refused: make it
owned by the user and remove group and other write permission. No data
migration is needed. From an earlier release, follow the
[v0.8.2 upgrade](v0.8.2.md#upgrade) first.

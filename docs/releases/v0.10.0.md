# Cairn v0.10.0

`v0.10.0` (`drystane-cairn==0.10.0`) follows v0.9.0. It moves semantic
extraction to `gpt-6-luna` before OpenAI retires `gpt-5.4-nano` on 1 April
2027, and it adds three client features: Claude Code lifecycle hooks, a
terminal browser for memories with explicit promotion, and access to a Cairn
behind Cloudflare Access. Garden loses the OpenCode HTTP adapter and gains an
experimental upgrade command for `garden-server` installations. The REST
contract, catalogue schema and Attic format are unchanged; the contract text
gains one caveat about `audit-read`. This release ships source and local build
recipes, not container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in
`deploy/images.lock` name local source-build tags. Garden remains Linux only.

## Semantic retrieval: extraction moves to `gpt-6-luna`

OpenAI shuts `gpt-5.4-nano` down on 1 April 2027 and names `gpt-6-luna` as its
replacement. Graphiti's medium role, which does extraction and batched edge
deduplication, now uses `gpt-6-luna`. The small role stays on `gpt-5.6-luna`
and embeddings on `text-embedding-3-small`. An installation that stays on
v0.9.0 loses projection of new facts when the old model shuts down.

The pinned graphiti-core 0.30.2 recognises reasoning models by a `gpt-5`
prefix. Left alone it would send `gpt-6-luna` a temperature and no reasoning
effort, which the provider accepts and then runs at medium effort. Cairn
therefore sends the request shape graphiti-core 0.31.2 uses for `gpt-6`
models: effort `none`, low verbosity and explicit prompt-cache mode. The
graphiti-core pin is unchanged.

The pinned models are now constants in `src/cairn/projection/models.py`, and
`docs/operations/pinned-models.md` lists them with their retirement dates and
the procedure for changing one. They are deliberately not operator
configuration: the embedding model is part of the stored vector identity, and
the language-model roles are chosen against quality evidence.

**Price and bound.**

- The medium model's name is part of the extraction cache key. That cache
  serves only the bulk path, `delivery.chunk_size` above 1. On such an
  installation the first `cairn rebuild-index` after the upgrade re-extracts
  every fact at provider cost. At the default chunk size of 1 extraction is
  never cached and a rebuild costs what it did before. Delivery of new facts
  is unaffected either way.
- Explicit prompt-cache mode turns provider prompt caching off. On a
  twelve-fact reference corpus the default mode wrote nearly every input token
  to the cache at 1.25 times the input rate and reused none, so explicit mode
  was the cheaper setting. A much larger run was not measured.
- On the same corpus, retrieval results were identical to those under
  `gpt-5.4-nano`. Accuracy of batched edge deduplication on `gpt-6-luna` was
  not measured separately.
- At list prices on 21 November 2026, `gpt-6-luna` costs half as much per
  input token as `gpt-5.4-nano` and 40% as much per output token.

## Client: Claude Code lifecycle hooks

`python -m cairn.client.claude_lifecycle install` writes a dedicated Claude
Code settings file whose hooks call the existing `cairn-memory` command.
`docs/claude-code-lifecycle.md` is the guide.

- **SessionStart** adds an arrival briefing for a query fixed at install time,
  labelled as untrusted evidence.
- **Stop** saves only the lines of one fenced `cairn-observations` block in the
  final reply, at most 8 lines of 4096 bytes each. A malformed or oversized
  block is refused whole. The transcript is never read.
- Recall on **UserPromptSubmit** and **PostToolUseFailure** is off by default
  and switched on per event at install time.

Hooks always exit 0 and return no decision, so they cannot block a prompt or
alter a reply. Saves are reported only from committed custody receipts.
Nothing is promoted, validated or corrected. `markdown-it-py` becomes a direct
dependency at its already locked version, because the Stop hook parses replies
with it.

**Bound.** Tested with Claude Code on Linux. Claude desktop and web, Codex and
native Windows are not covered. If the host kills the session-start hook after
the visit is acknowledged, that briefing is lost.

## Client: `cairn-memory browse`

`cairn-memory --profile P browse` is a terminal UI for scrolling through
memories, newest first, in the profile's scope and its ancestors. It opens a
memory in full with its history and reads its source evidence. `/` searches by
relevance and `f` filters by trust. It uses Python's `curses` and adds no
dependency. Memory text is untrusted: every non-printing character is drawn as
a visible escape.

A candidate can be promoted from the UI through the existing proposal flow. It
is offered only to a profile holding both `ingest` and `promote`, only for
facts at the exact profile scope, and only for a fact with its own source
evidence. A reason and a confirmation are required. An unknown outcome is
never shown as promoted and can be resent identically.

**Bound.** A snapshot holds at most 4096 facts and says so when the selection
is incomplete. The trust filter runs in the client.

## Client: Cloudflare Access and proxy refusals

A connection profile may carry a Cloudflare Access service token in two paired
fields, `access_client_id_file` and `access_client_secret_file`. When present,
both headers go on every request. `docs/memory-connection-profiles.md`
documents them.

A 401 or 403 without Cairn's failure envelope is now reported as
`upstream_access_denied` with the proxy's status code, and its body is never
disclosed. On the preflight and on reads this is a confirmed refusal with exit
code 2; it used to be `http_error` with exit code 4. On a dispatched mutation
the outcome stays unconfirmed, because a proxy can forward a request and
replace Cairn's receipt.

**One behaviour change, by Operator's ruling of 11 November 2026.** The profile's
`credential_file` and both service token files must be owned by the invoking
user with no group or other access: mode 0600 or 0400. Anything wider is
refused before any request, with `credential_not_protected` or
`access_credential_not_protected`. Check existing credential files before
upgrading clients.

`remember` no longer keeps the server's failure message text. A failure code
outside the closed vocabulary is reported as `http_error`.

## Garden

- **The OpenCode HTTP adapter is removed**, by Operator's decision of 8 November
  2026. OpenCode is supported only through the in-process plugin under
  `opencode --standalone`. `garden attend` is Codex-only. A profile with
  `"adapter": "opencode"` is refused with a message naming the plugin; the
  legacy home import still reads such profiles and keeps the identity.
- **`garden-upgrade` for `--mode garden-server` is experimental.** The Garden
  account takes and restores the cold copy, both units are disabled while they
  are stopped, and an unguarded backup hook is refused before the upgrade
  starts. It is tested against fakes only. Take your own backup of
  `/var/lib/garden` and `/etc/garden` first; the hand procedure in
  `docs/operations/managed-garden.md` remains the reference.
- **A silent daemon socket is re-dialled.** The stream probe is bounded to 2
  seconds. On failure the cached connection is dropped and re-dialled once. A
  socket that stopped carrying traffic without closing used to make every call
  wait 35 seconds and fail with "Garden stream unavailable".

## Contract text: `audit-read` and content digests

Ingest audit events carry unkeyed SHA-256 digests of the command and the
evidence. A holder of `audit-read` can use them to confirm a guessed fact body
or payload. By Operator's decision of 8 November 2026 the behaviour stands and the
contract and client guide now state it: grant `audit-read` only to principals
already trusted to read the content at that prefix. No code or event changed.

## Other changes

- `docs/fresh-session-correction-demo.md` is a five-minute walkthrough in
  which a fresh session finds a fact, corrects it and keeps the history. A
  deterministic checker and a test that runs every block accompany it.
- The demo verifier counts zero-test summaries, collection errors and nonzero
  exits as failures.

## Upgrade

From v0.9.0:

1. Rebuild the image and restart Cairn; there is no migration. Do this before
   1 April 2027 if semantic retrieval is enabled.
2. If `delivery.chunk_size` is above 1, budget for one full re-extraction at
   the next `cairn rebuild-index`. No rebuild is needed for the upgrade itself.
3. Before upgrading clients, set each profile's credential file to mode 0600
   or 0400, owned by the user who runs the client.
4. Replace any Garden profile that uses the OpenCode HTTP adapter with the
   OpenCode plugin.

# Cairn v0.7.16

`v0.7.16` (`drystane-cairn==0.7.16`) is a patch release on v0.7.15. It makes the
secret screen's labelled-word rule default-deny, so that a labelled word
passphrase in a format the screen did not list is now refused. v0.7.15 was not
published or deployed, so upgrade from v0.7.14 straight to v0.7.16. The v0.7.15
notes still describe its other changes: the Garden first-open retry, the
`cairn_migrate overlay` timestamp check, `--falkordb-image` for the semantic
evaluator and the ChatGPT instructions note. Cairn's REST, MCP and memory
contracts, catalogue schema and Attic format are unchanged. This release
ships source and local build recipes, not container images: `CAIRN_IMAGE` and
`CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local source-build tags.

## Secret screen

**Default-deny labels (`contextual-entropy`).** v0.7.15 refused a labelled
word-shaped candidate only when the label was one of the syntaxes it
recognised, and labelled word passphrases in other common formats passed.
Now a word-shaped candidate after its keyword is unlabelled only when the gap
between them is plain single-line prose containing at least one letter. Anything
else labels the candidate: a colon, `=`, a quote (typographic ones included), a
bracket, a newline, a gap with no letters (`PASSWORD X`, `Bearer X`,
`password (X)`, `set $password X;`), `is` or `was` alone, a `>` straight after
the keyword (`<password>X`), or plain spaces after a `--` flag containing the
keyword (`--secret-key X`). An arrow (`token -> X`) remains prose. The run-start
rule and candidates before the keyword are unchanged.

**Price.** Status notes are refused again when a colon or quotes come between
the keyword and an identifier, or when the identifier follows the keyword
directly. Examples include `token rotation: relay-credential-alpha-host
restarted`, `Credential "relay-credential-alpha-host" rotated today` and
`the token relay-credential-alpha-host was rotated`. Reword by putting a word
between the keyword and the identifier: `the token for relay-credential-alpha-host
was rotated`, or `the credential path is relay-credential-alpha-host`. Never
place an identifier directly after *token*, *secret*, *credential* or
*password*.

**Accepted residuals.**

- Prose with words between keyword and value passes, including `the vault
  password, for the record, winter-meadow-copper-lantern`.
- Arrows pass: `token -> winter-meadow-copper-lantern`.
- A digit directly after a run-start keyword removes that prefix label, as in
  v0.7.15: `password1-winter-meadow-copper-lantern` passes.
- Valid file extensions exempt candidates, labelled or not:
  `credential: winter-meadow-copper-lantern.txt` passes.

**Bound.** The rule refuses a subset of what v0.7.14 refused, because every
refusal still needs the v0.7.14 entropy trip inside the same window. Policy
identity stays `cairn.secret/v1`. v0.7.15 was never published, so no
installation admitted data under its narrower rule and no rescan is needed.

Agents should retain reword-to-avoid guidance for candidates the screen refuses.

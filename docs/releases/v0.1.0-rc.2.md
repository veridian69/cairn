# Cairn v0.1.0-rc.2

`v0.1.0-rc.2` (`drystane-cairn` package version `0.1.0rc2`) is a release
candidate for Cairn's v0.1 scoped, evidence-aware memory authority. It is not a
stable or long-term-support release.

## Highlights

- Authenticated exact-evidence reads are available through REST
  `POST /v1/read-evidence` and MCP `read-evidence`. Successful reads preserve
  the accepted UTF-8 source bytes and return their SHA-256 digest. Existing
  realm, scope, grant and classification checks still govern disclosure.
- The Linux guided installer supports disposable, persistent native and Docker
  modes, with resumable recovery and removal. Attic-only operation requires no
  model-provider credential; semantic search remains optional and requires an
  OpenAI API key.
- The custody and administration API and the conversation-oriented memory API
  share one authoritative catalogue. Corrections, invalidations,
  disagreements, provenance, durable mutation receipts and retrieval
  reconciliation retain their v0.1 contract semantics.
- Source, Compose and Kubernetes installation paths include inline Attic
  write/read verification. Native Windows support remains limited to the
  `cairn-mcp` STDIO relay to a trusted Linux-hosted deployment.

Reading exact evidence returns stored source material; it does not establish
that the material or any claim derived from it is true.

## Installation and images

Clone the public repository and run the guided installer on Linux `x86_64`:

```sh
git clone https://github.com/veridian69/cairn.git
cd cairn
./cairn-install
```

For source development, use Python 3.12 and uv 0.12.0, then run
`uv sync --locked`.

This release candidate does not publish a Cairn container image or registry
digest. `cairn:v0.1.0-rc.2` in `deploy/images.lock` and the committed deployment
renders is a local build tag. Build it from the trusted checkout or supply a
separately reviewed immutable image digest when deploying to a cluster.

## Validation boundaries

The complete local repository gate is:

```sh
make check
```

GitHub pull-request and `main` push runs perform lightweight policy and wheel
checks plus the image build, smoke test and vulnerability scan. The scheduled
workflow runs the image gate. The hosted full repository check runs only by
manual dispatch and excludes marked real Bubblewrap/namespace tests. Optional
host-isolation diagnostics are a separate manual workflow and do not replace
local `make check` or deployment-specific acceptance.

## Operational boundaries

- Cairn serves plain HTTP; deployments beyond numeric loopback need TLS and
  rate limiting at a trusted reverse proxy or ingress.
- One serving process owns each SQLite data directory, which must provide
  reliable POSIX locking and `fsync` semantics.
- Kubernetes deployment requires a reviewed Cairn image by immutable digest
  and site-specific storage, admission, network-policy and ingress checks.
- The OpenShift overlay is statically validated; this release candidate makes
  no OpenShift target-acceptance claim.
- Semantic retrieval calls an external model provider and can incur charges.
  Catalogue custody, lifecycle, audit and exact Attic reads work without it.

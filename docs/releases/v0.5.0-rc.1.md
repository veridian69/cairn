# Cairn v0.5.0-rc.1

`v0.5.0-rc.1` (`drystane-cairn==0.5.0rc1`) is an unpublished dependency and
platform refresh candidate. Publication, signing and deployment are separate
steps. The versioned REST/MCP contract and server-enforced authority, custody,
scope and exact-evidence guarantees are unchanged.

## Dependency changes

- uv 0.12.14 and refreshed runtime, build and test dependencies.
- Graphiti 0.30.2, FalkorDB Python client 1.7.1 and Redis 8.1.0, retaining
  hiredis. FalkorDB server 4.20.4 now uses Cairn’s maintained server-only
  runtime `v4.20.4-cairn.1`, with Redis 8.6.3 and refreshed Debian packages.
- OpenAI 3.14.0 with a dedicated HTTPX2 dependency. Graphiti's LLM, embedding
  and reranking roles continue to share one explicitly bounded provider pool.
- MCP 1.30.0. MCP 2.2.0 was investigated and rejected because importing its
  low-level server eagerly loads OAuth endpoint modules prohibited by Cairn's
  accepted runtime import boundary. The supported MCP protocol remains
  `2025-11-25`.
- Python support is 3.12–3.14 with uvloop 0.22.1; the managed and container
  runtime defaults to Python 3.14.7. Validation is recorded separately.
- Go language minimum 1.26.0, toolchain 1.26.8 and `golang.org/x/sys v0.48.0`.

## Operator implications

Graphiti's version is part of extraction and edge-timestamp cache identity.
A rebuild with this version can re-extract material previously cached under
0.29.3, incurring provider charges. Plan and authorise any productive rebuild
separately. Embedding cache identity is unchanged. No cache or productive data
is deleted or rebuilt by release preparation.

The disposable cluster pins move to kind 0.33.0, Kubernetes/kubectl 1.35.8 and
Calico 3.32.2. Existing recorded production Kubernetes/Cilium pins remain
unchanged; disposable checks do not certify a production-cluster upgrade.

The gateway candidate uses an exact Squid 7.2/Ubuntu 26.04 edge digest because
both previous 6.6 channels contained fixable high-severity vulnerabilities.
The manifest starts `/usr/sbin/squid-gnutls` explicitly, preserving the existing
UID/GID, read-only root, writable volumes and network policy. This changes the
vendor channel and launcher contract; use the candidate's complete manifests.

## Validation boundaries

See the [candidate dependency inventory](../evidence/release/v0.5.0-inventory.md).
Tests use disposable catalogues, a real disposable FalkorDB and local synthetic
provider responses. They establish transport, scope and lifecycle behaviour;
they do not measure extraction quality across a representative corpus. Separate
authorised reference installer tests exercised live OpenAI semantic retrieval,
paraphrased lookup, exact Attic evidence and restart persistence. No productive
migration, hosted CI run or public release is implied.

## Maintained FalkorDB runtime

Cairn v0.5 selects our patched, digest-pinned FalkorDB server runtime. It retains
the vendor's exact 4.20.4 module and incorporates the package-upgrade failure
handling fix submitted in [upstream PR #2838](https://github.com/FalkorDB/FalkorDB/pull/2838).
The browser is excluded. The recorded scan has zero fixable HIGH/CRITICAL
findings and 36 HIGH findings without available fixes; this is not a claim of
zero vulnerabilities.

The first derivative supports Linux amd64. See the [runtime release instructions](../../deploy/falkordb/README.md)
for the exact image, offline import, build provenance and corresponding source.
This candidate is not yet published to the registry; preload the verified archive
before running a semantic installation. Normal registry pulls retain the existing
Docker minimum; offline index-preserving import requires a containerd image store.

When an upstream release incorporates the fix, integrate its image and any required
application changes, repeat compatibility/security/semantic/Attic checks, then
publish a new Cairn release. Existing release pins are immutable.

# Cairn v0.11.6

`v0.11.6` (`drystane-cairn==0.11.6`) is a patch release on v0.11.5. It makes
recall faster where the optional Graphiti index is enabled: a search no longer
re-proves the integrity of a whole partition's derived records every time. The
REST contract, the memory OpenAPI contract, the memory MCP manifest, the
catalogue schema, the Attic format and every stored record are unchanged. No
migration or index rebuild is required, and search returns what it returned
before. This release ships source and local build recipes, not container
images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags. Garden remains Linux only.

## Recall no longer walks the whole partition on every search

**What was slow.** Before returning semantic candidates, a search checked that
every fact in each requested partition has complete, well-formed derived
records (its fact vector and, with local units, its clause units). It did so
four times per search: two checks up front, and the same walk again inside the
two statements that select candidates. On a deployment of about 4,000 facts
with 32,000 clause vectors those walks took 5 to 6 seconds of a 7 to 9 second
recall. The cost grew with every stored fact, and the slowest single query
stood at more than half of the index's 5 second query limit; past that limit
recall would have lost its semantic stage.

**What changes.** A partition that has passed the checks keeps that verdict in
memory, and later searches of it only score candidates.

- A search of a partition with no verdict is checked in full, exactly as
  before, and a pass establishes the verdict. After a start the first search
  of each partition is therefore the slow one.
- A projection into a partition withdraws its verdict while it runs. The
  verdict is restored when the last overlapping projection ends only if one
  was held before, every one of those projections succeeded, the facts they
  wrote pass the same checks by name, and the partition's graph holds exactly
  one fact vector (and, with local units, one header) per episode and nothing
  of another partition.
- `clear`, an index marked unverified, any failure of a scoring scan, and
  record counts that differ from those stored with the verdict all withdraw
  it. A projection whose call timed out or was cut short by shutdown leaves
  its partition without a verdict until the next start.
- A search that a projection begins to overlap is refused as before, and
  recall answers without semantic candidates for that request.
- A search keeps no state for a partition it merely asks about, and an empty
  partition gets no verdict, so the number of verdicts held is bounded by the
  partitions that hold facts.

**Measured.** On the same data, against the pinned index runtime, the semantic
stage of one search took about 5.3 seconds fully checked and about 0.35
seconds with a verdict. The selected candidates and grades are identical,
exact ties included.

**Its price.** A derived record altered underneath the running process, in a
way that leaves every record count unchanged, is no longer found by the next
search. It is found by the next fully checked search, by the start-up audit
and by `repair-index`. Cairn's own writes cannot produce that state; an index
store restored or edited underneath a running Cairn can, so restart Cairn
after any such intervention. A graph that holds a record of another partition
never gets a verdict and has no log event of its own: every search of it pays
the full check.

**Residual.** The scoring scans still read every stored vector, so recall
still grows in line with the number of stored facts, from a much lower base.
The index's own relationship search is unchanged.

`docs/operations/semantic-fact-search.md` describes the behaviour for
operators.

## Upgrading

Replace the server image and restart. Nothing else changes: no configuration
key, no migration, no rebuild. The MCP relay and Garden are unchanged in this
release apart from their version.

# Cairn v0.7.13

`v0.7.13` (`drystane-cairn==0.7.13`) adds ordered, continuable memory recall and
bounded evidence inspection to the memory REST and MCP surface. The additions are
new operations: existing `recall`, `history` and the core `/v1` operations keep
their request and response packets.

- `recall-page` returns relevant, currently valid memories in relevance, newest
  or oldest order, with an opaque cursor for more results. Source-time ordering
  uses the authorised assertion `observed_at`, labelled as a source claim, never
  inferred from prose, identifiers or `valid_from`. Ranking and membership are
  frozen per snapshot; permissions are rechecked on every page, and a
  source-ordered continuation whose authorised source-time projection changed is
  refused with `continuation_unavailable`. Snapshots are ephemeral, bounded and
  dropped on restart.
- `evidence-window` returns a bounded, byte-exact window of one verified evidence
  payload, anchored by a literal-terms query or a byte offset, so a recalled hit's
  `source_evidence_id` can be inspected in context.
- The Python client and CLI gain `recall-page` and `evidence-window`. Host
  workflows recall through `recall-page` and gain a read-only `source_window`
  tool once the server reports `product_version` 0.7.13 or later, and fall back to
  the legacy `recall` against an older server.
- A recall query that is not valid UTF-8, such as a JSON-escaped lone surrogate,
  is now an `invalid_request` wire rejection on `recall` and `recall-page`
  instead of an `internal_error`. Wire rejections of `recall` are now audited as
  `memory-recall` deny, as for `recall-page` and `evidence-window`.

The catalogue schema, Attic format and the core REST and MCP contracts are
unchanged; the memory contract gains the two operations. This release ships
source and local build recipes, not container images.

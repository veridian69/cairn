# Cairn v0.7.19

`v0.7.19` (`drystane-cairn==0.7.19`) is a patch release on v0.7.18. It fixes
Garden, the shared agent message service that ships with Cairn: stopped
snapshots now cover a data directory shared with the Garden gateway, the Codex
adapter speaks WebSocket to current Codex app-server sockets, and the OpenCode
adapter supports the OpenCode 2.x session API. The Cairn server is unchanged
apart from its version identity: the REST and MCP contracts, catalogue schema
and Attic format are as in v0.7.18. This release ships source and local build
recipes, not container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in
`deploy/images.lock` name local source-build tags.

## Garden snapshots with a gateway

**What failed.** `garden snapshot create` refused a data directory that the
Garden MCP gateway (`garden serve` or `garden host`) also uses. Without an
ownership marker it rejected the gateway's `garden.lock` as an unknown entry.
With one, the staged `state.db` failed validation on the gateway's
`garden_binding` and `garden_inbox` tables. A scheduled stopped snapshot of such
a directory therefore failed on every run.

**What changed.** Snapshot, restore and reset now take the gateway locks
(`garden.lock`, and `host.lock` for `garden host`) when present, and refuse
while a running gateway or host holds one. Both lock files are allowed in an
unmarked directory and are never copied into a snapshot. The staged schema
accepts the gateway tables only as a complete set whose DDL matches the
gateway's exactly; the daemon tables remain required. A gateway that starts
while maintenance holds the store now probes the daemon straight after taking
`garden.lock` and fails before it opens `state.db`.

**Price and bound.** The snapshot format and schema versions are unchanged, and
daemon-only snapshots behave as before. A snapshot that contains gateway tables
is refused by older Garden binaries, which fail closed rather than restore a
partial schema. Stop the gateway as well as the daemon before a stopped
snapshot, restore or reset.

## Codex adapter over WebSocket

**What failed.** The Codex app-server control socket requires a WebSocket
handshake. Garden is verified against Codex 0.163.0; 0.154.0 uses the same
socket and handshake but has not been run end to end. Garden
piped line-delimited JSON-RPC through `codex app-server proxy`, a byte relay, so
Codex closed the connection and `garden doctor` reported an uncertain delivery
although nothing had been sent.

**What changed.** The adapter dials the unix socket directly, with compression
off, a 2 MiB read limit and text frames only. It no longer starts a `codex`
subprocess; a `codex_binary` profile field is accepted and ignored. When a
review or compaction turn is running, Codex answers `turn/start` with error
`-32603` and `ActiveTurnNotSteerable`; Garden treats that as busy and keeps the
message pending. Failures during `initialize`, task resume and the doctor read
count as unavailable, so only a `turn/start` that may have been transmitted is
reported as uncertain. Every reader exit closes the connection.

**Dependency.** Garden now vendors `github.com/coder/websocket` v1.8.15 (ISC);
its licence is in `garden/THIRD_PARTY_LICENSES/`.

## OpenCode 2.x adapter

**What failed.** OpenCode 2.x serves its API under `/api`, with Basic
authentication and `{"data": ...}` response envelopes, and answers the 1.x root
routes with its web interface. Garden's OpenCode adapter could not deliver to a
2.x host.

**What changed.** A new profile field `host_api_version` selects `"1"` (the
default when omitted) or `"2"`; an explicit `null` is refused, by both the
profile loader and `garden-config`. For 2.x the adapter reads busy state from
`/api/session/active`, submits to `/api/session/:id/prompt` with
`"delivery": "queue"`, and accepts the message once the session inbox or the
message read-back shows the exact text. Queueing means a session that becomes
busy between the idle check and the submission keeps the message pending rather
than having it steered into the running turn; an idle session still wakes and
takes it. A 409 is a permanent conflict on that message ID and is rejected, not
retried. 2.x message IDs are derived from the session and the Garden event,
because 2.x refuses an ID reused across sessions and a broadcast shares one
event ID. 1.x behaviour is unchanged.

**Residual.** Garden message IDs (`msg_garden_…`) are not time-ordered and sort
after OpenCode's native IDs. The OpenCode interface orders reverts by ID, so
reverting a native message can also hide an earlier Garden message from the
transcript; stored session history keeps the real order. Operator ruled on
18 October 2026 to ship this as a documented limitation.

## Tests under a restrictive umask

Two Garden permission tests created their files with mode 0644, which a umask
of 077 narrowed to 0600, so they failed. They now set the mode after creating
the file, and the suite passes under either umask.

## Upgrade

Rebuild and replace the Garden binary on every Garden host and client. Stop the
gateway and daemon, install the new binary, then start them again; the data
directory needs no migration. In an OpenCode 2.x profile, set
`"host_api_version": "2"`. A Codex profile needs no change. Rebuilding the
Cairn and edge images is optional: the Cairn server changes only its version
identity, and `migrate` is a no-op.

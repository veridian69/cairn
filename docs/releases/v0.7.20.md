# Cairn v0.7.20

`v0.7.20` (`drystane-cairn==0.7.20`) is a patch release on v0.7.19. v0.7.19
was tagged but not published on its own, so this is the first published release
to carry its Garden changes; read the [v0.7.19 notes](v0.7.19.md) first.
v0.7.20 fixes one gap that v0.7.19 left in the installer's Garden participant
bundles. The Cairn server is unchanged apart from its version identity: the
REST and MCP contracts, catalogue schema and Attic format are as in v0.7.18.
This release ships source and local build recipes, not container images:
`CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags.

## OpenCode participant bundles choose a host API version

**What failed.** v0.7.19 added the OpenCode profile field `host_api_version`,
which defaults to `"1"` when omitted. The participant bundles that the installer
writes for a managed Garden (`--garden-config`) left the field out of
`opencode.profile.example.json`. A profile copied from such a bundle therefore
selected the OpenCode 1.x routes, and could not deliver to an OpenCode 2.x
server.

**What changed.** The generated OpenCode profile now carries
`"host_api_version": "REPLACE_WITH_1_OR_2"`, and the bundle's `README.md`
explains the choice: `"2"` for an OpenCode 2.x server, `"1"` for 1.x. Garden
cannot tell the generations apart, because a 2.x server answers 1.x paths with
its web interface. The profile loader refuses the placeholder until it is
replaced, in the same way as the bundle's other `REPLACE` values.

**Price and bound.** Only newly generated bundles change. A bundle written by
v0.7.19 or earlier keeps working for OpenCode 1.x. For OpenCode 2.x, add
`"host_api_version": "2"` to its `profile.json` by hand. Claude and Codex
bundles are unchanged.

## Upgrade

From v0.7.18, follow the v0.7.19 upgrade: rebuild and replace the Garden binary
on every Garden host and client, stopping the gateway and daemon first; the
data directory needs no migration. In an OpenCode 2.x profile, set
`"host_api_version": "2"`.

From v0.7.19, Garden's sources are unchanged; a rebuilt binary differs only in
the version it reports, which snapshots record as `binary_version`. Keep every
host and client on the same build so that recorded and running versions agree.
Rebuilding the Cairn and edge images is optional: the Cairn server
changes only its version identity, and `migrate` is a no-op.

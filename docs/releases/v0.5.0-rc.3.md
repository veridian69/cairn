# Cairn v0.5.0-rc.3

`v0.5.0-rc.3` (`drystane-cairn==0.5.0rc3`) is a release
candidate, not a stable or long-term-support release. The versioned REST/MCP
contract and server-enforced authority, custody,
scope and exact-evidence guarantees are unchanged.

## Candidate scope

This candidate carries the previously validated dependency refresh and Cairn's
maintained FalkorDB runtime. Its dependency set includes uv 0.12.14, Graphiti
0.30.2, FalkorDB Python client 1.7.1, Redis 8.1.0, OpenAI 3.14.0, MCP 1.30.0,
Python 3.12–3.14 support and a Python 3.14.7 managed/container default. The
maintained FalkorDB server runtime remains `v4.20.4-cairn.1`; it is digest
pinned, excludes the browser and retains the recorded security and
corresponding-source boundaries. See the [candidate dependency
inventory](../evidence/release/v0.5.0-inventory.md) and the [runtime release
instructions](../../deploy/falkordb/README.md).

The dependency refresh and maintained FalkorDB acceptance have already been
validated. They do not imply that this candidate has been published to a
registry or that a signed Cairn image digest exists.

## Installation and downloads

Use a trusted checkout of tag `v0.5.0-rc.3`, Python 3.12–3.14 and uv 0.12.14.
Run `./cairn-install` for the guided installer. macOS native mode supports local
catalogue memory and Attic; Linux also supports optional semantic search.

The release downloads include the Python wheel, source distribution and
`SHA256SUMS`. Linux semantic installations additionally need the maintained
FalkorDB image, which is distributed as an offline archive in this candidate:

- [Maintained image archive](https://github.com/veridian69/cairn/releases/download/v0.5.0-rc.3/cairn-falkordb-v4.20.4-cairn.1.tar).
- [Matching corresponding source, build inputs and component notices](https://github.com/veridian69/cairn/releases/download/v0.5.0-rc.3/cairn-falkordb-v4.20.4-cairn.1-source.tar.gz), available at no charge alongside the binary.
- [Release checksums](https://github.com/veridian69/cairn/releases/download/v0.5.0-rc.3/SHA256SUMS).

Follow the [verified archive-loading procedure](../../deploy/falkordb/README.md)
before enabling semantic search. Loading this archive requires Docker's
containerd image store to preserve its full OCI index. The descriptor verifies
the archive checksum and image digest. No FalkorDB GHCR publication is claimed.

Cairn's `cairn:v0.5.0-rc.3` image remains a local build tag. This release does
not publish a Cairn registry image, signed container digest or new image scan;
historical security assessments retain their own image/revision identities.

## macOS native evidence

macOS foreground memory and Attic acceptance passed on both Intel and Apple
Silicon runners in run `34975380517`. This establishes the recorded foreground
native path on those architectures.

Native background memory and Attic acceptance also passed on both architectures
in run `35002709257`, at `0f993ef013d168a337ab6b07b6cf6ab108d98f99`. Each
runner passed 145 focused tests, followed by real launchd installation, restart,
foreign-service protection, delayed shutdown, rollback/resume and removal.
Memory corrections, disagreements and exact Attic bytes survived restart and
resume. Use the [macOS native guide](../operations/macos-native.md).

The tested hosts were macOS 26.6.1 Intel and macOS 26.6.2 Apple Silicon, with
Python 3.14.7. Actual logout/login and macOS 12.7.6 remain untested; semantic
graph search remains Linux-only. Linux `make check` passed with 6,659 tests and
136 skips before the subsequent acceptance-fixture and timeout corrections;
application and installer source is unchanged from that full-check revision.

The everyday-memory guide now states that `arrive` and `remember` require both
`retrieve` and `ingest` grants. A diagnostic `ready` result does not authorise
every command.

## Validation boundaries

Tests use disposable catalogues, a real disposable FalkorDB and local
synthetic provider responses. They establish transport, scope and lifecycle
behaviour; they do not measure extraction quality across a representative
corpus or authorise productive migration, a registry push or a public release.

Historical RC1 release notes and their evidence remain records of that
candidate; they are not rewritten by this RC3 promotion.

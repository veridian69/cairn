# Cairn v0.8.2

`v0.8.2` (`drystane-cairn==0.8.2`) is a patch release on v0.8.1. Neither
v0.8.0 nor v0.8.1 was published on its own, so this is the first published
release since v0.7.20 and carries their changes; read the
[v0.8.0 notes](v0.8.0.md) first, then the [v0.8.1 notes](v0.8.1.md). v0.8.2
fixes one defect in the backup hook that `install --mode garden-server`
generates. The Cairn server and Garden are unchanged apart from the version
identity: the REST and MCP contracts, catalogue schema and Attic format are as
in v0.7.18. This release ships source and local build recipes, not container
images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags.

## The garden-server backup hook removes the snapshot it archived

**What failed.** The generated `/usr/local/bin/garden-backup` took a Garden
snapshot, archived it into the export directory and left the staged snapshot
under `/var/lib/garden/.garden/backups`. Garden keeps no snapshot retention of
its own, so every run kept one more full copy of the Garden data on the host.
The installer's own `garden-backup` for native and Docker installations already
deletes its staged snapshot once the archive is verified; the server hook did
not.

**What changed.** Once the archive is published, the hook renames the staged
snapshot to a dot-prefixed marker, which Garden's snapshot listing ignores, and
removes every such marker, so an interrupted removal is never seen as a
snapshot and the next run finishes it. It does this under Garden's shared
runtime lease, as the running daemon would hold it, so a stopped-only
`garden snapshot list` or `restore` cannot overlap the removal; if the lease is
held for five minutes the run fails and alerts with the archive already
published and the snapshot in place. The hook also accepts only a plain
snapshot id from `garden snapshot create`: no leading dot or dash, no slash,
since the id names what `tar` reads and what is removed.

**Price and bound.** The published archive is the retained copy; retention of
archives in the export directory belongs to whatever consumes it, as before. A
hook written by v0.8.0 or v0.8.1 keeps accumulating snapshots until the
installation is reinstalled or the hook is replaced by hand; no such
installation is known. The Codex review that found the defect also noted that a
lease timeout exits without a message of its own; the failure is still
reported by the unit's `OnFailure` alert.

## Upgrade

From v0.7.20, follow the [v0.8.0 upgrade](v0.8.0.md#upgrade). From v0.8.0 or
v0.8.1 with a garden-server installation, reinstall the hook from this release;
otherwise no action is needed, because only the version identity changes.

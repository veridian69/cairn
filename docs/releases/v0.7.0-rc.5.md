# Cairn v0.7.0-rc.5

`v0.7.0-rc.5` (`drystane-cairn==0.7.0rc5`) corrects the installer and
operator-documentation defects found during blind rc.4 acceptance. It retains
the operator-built FalkorDB runtime, managed Garden and four guided Cairn
installation modes. It does not change the catalogue schema, Attic format or
versioned REST/MCP contracts.

## Installation corrections

- Attic-only Kubernetes workloads now receive the required writable-volume
  `fsGroup`, while Garden's stricter user and group policy remains conditional.
- Kubernetes rollout failures report safe Pod and container reason fields, and
  preloaded-image proof uses the exact disposable Pod rather than the
  incomplete `Node.status.images` inventory. Garden continues to pull its
  published image normally.
- The interactive wizard can collect every semantic prerequisite for native,
  Docker and Kubernetes installs. Resume refuses explicit mode, port or
  semantic options which contradict recorded state, while `status` no longer
  rewrites that state.
- Garden gets clear stage names in progress output and `ls`, and its listener
  port is checked before credentials are enrolled or runtime preparation
  starts. Failed rollback records a failed state rather than retaining a stale
  verified result.
- Runtime composition disables Graphiti's optional third-party telemetry before
  constructing its adapter. Instance removal continues to leave unrelated
  user-level caches and external provider-key input files alone.
- Diagnostics preserve stdout-before-stderr ordering. The guides now spell out
  SSH-to-localhost staging, scoped Kubernetes RBAC checks, safe shared-gateway
  removal, provider-key ownership, and guarded placeholders. The landing page
  uses a distributor-supplied repository URL and states that Garden is not
  supported on macOS.

## Publication and acceptance boundary

This is a **Gitea-only** release candidate. Do not publish it to GitHub. The
release contains the FalkorDB build recipe and staging tools, but no FalkorDB
image archive, source bundle or GHCR publication. Operators build and retain
their own reviewed database runtime.

Rc.5 requires a new blind run from a fresh public export. That run must follow
only the published installation instructions and exercise disposable, native,
Docker and Kubernetes installations, including semantic and managed-Garden
paths, before rc.5 is accepted.

# Cairn v0.11.5

`v0.11.5` (`drystane-cairn==0.11.5`) is a patch release on v0.11.4. It makes
every `cairn-memory` function reachable from the terminal browser, puts the
text the memory MCP server sends as its instructions under the existing
contract digest, and fixes three faults: one in the edge-resolution batcher
and two in how Garden reports a failure. The REST contract, the memory
OpenAPI contract, the catalogue schema and the Attic format are unchanged.
The memory MCP manifest gains one key, so `mcp_contract_digest` for
`cairn.memory/v1` changes. No migration or index rebuild is required. This
release ships source and local build recipes, not container images:
`CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags. Garden remains Linux only.

## The terminal browser reaches every memory function

`cairn-memory --profile PATH browse` could list, search and open memories,
read their evidence and promote a candidate. It now also offers:

- **`P`, pending proposals.** A read-only list through `proposal-list`, and a
  full read of one through `proposal-read`. `x` there rejects a pending
  proposal.
- **`s`, suggestions** for the selected or open fact, through `suggest`.
  Nothing is executed or persisted.
- **`c`, connection and grants.** What `check` reports, with the four
  permissions and which browser functions they allow. It re-reads the
  diagnosis on opening and on `r`.
- **`x`, `X`, `d`, with `m`.** Correct a fact, correct it superseded by a
  marked fact, or record a disagreement with the marked fact.
- **`S`, the session view.** `status` on opening, and `arrive`,
  `acknowledge-visit`, `remember`, `resume` and `abandon`.

**Every write is confirmed.** A key only opens an input. A confirm screen then
shows exactly what will be sent, and the request goes out only on `y`. A
receipt is reported as recorded; a refusal shows its code and that nothing
changed; an unknown outcome is shown as unknown, never as success or failure,
and can be resubmitted with the same idempotency key. On exit with an unknown
outcome the browser prints the command and input for an identical
resubmission and exits 3.

**"Saved" needs a custody receipt.** In the session view only a committed
turn that carries its custody receipt is reported as saved. `prepared` means
Cairn holds the output and fact custody is not confirmed.

**Bounds.** The browser corrects one fact at a time, at the profile's exact
scope. `remember` takes up to eight observation bodies without the optional
timestamps and without `replaces_turn_id`; the command line remains the way to
supply those. `acknowledge-visit` works for the visit the browser's own
`arrive` issued in the same run, because `status` reports no visit ID.
Functions the profile's grants do not allow are hidden and refused with a
message. `proposal-reject` also needs `promote` at the proposal's target
scope, which the diagnosis does not report, so the server may still refuse
it. At 80 columns the list footer leaves out some bindings; the key table in
`docs/everyday-memory.md` has them all.

**Not exercised.** The new views are tested through the controller and
against a disposable local server, not in a real terminal session against a
deployed server.

## The contract digest covers the server instructions

**What was wrong.** The memory MCP server sends connector conventions in the
`instructions` field of `initialize`. That text becomes part of a client's
prompt, yet no contract file contained it, so it could change while
`contract_digest` and `mcp_contract_digest` stayed the same.

**The fix.** `contracts/cairn-memory-mcp-tools-v1.json` has a new top-level
`instructions` key holding the text, with `<realm>` in place of the realm.
`mcp_contract_digest` is the SHA-256 of that file, so a changed text changes
the digest. The tools and failure codes are unchanged.

**Operator step.** `mcp_contract_digest` for `cairn.memory/v1` is now
`ba191049219e4b7f0d355360ba0f25afabc7258eb1413148f8ffa755636c88a1`. Update
any place that pinned the previous value. The Garden installer compares a
server's digests with its own source distribution, so run the installer from
the same release as the server.

**Limits.** The digest shows drift from a reviewed file; it is no defence
against a hostile server, which answers `diagnose` itself. An MCP client has
read the instructions before it can call any tool, so the check serves
operators and installers. The realm is deployment configuration and lies
outside the digest.

## Edge resolution: a finished batch no longer leaves callers waiting

**What was wrong.** The batcher that combines edge-resolution calls settled
its callers from inside the batch task. A task cancelled before its first
step, or one that failed outside its own handlers, ended without settling
them, and they waited until their caller's deadline.

**The fix.** When a batch task ends, any caller it left unanswered is
cancelled or given the task's error.

**Bound.** In the shipped delivery path the only canceller of a batch is the
cleanup of the bulk call the callers belong to, which cancels them too, so
this is hardening; no stranded caller was observed.

## Garden says why its embedded server did not start

**What was wrong.** Garden runs its embedded NATS server with logging off. A
start that failed inside it surfaced only as "NATS server not ready" after
five seconds.

**The fix.** The error carries the server's own reason, and the wait ends as
soon as the server reports that it has given up.

**What this explained.** Occasional "not ready" failures under many
concurrent test runs were `bind: address already in use` on port 0: the host
had run out of ephemeral ports. A single run of the suite stays well below
that.

## Garden names a command sandbox when it refuses its home

**What was wrong.** Inside a user namespace that maps only the caller, such
as the command sandbox some agent hosts use, a root-owned parent of the
Garden home appears with an unidentifiable owner. Garden refused with "owned
by another user", which reads as a broken installation.

**The change.** The refusal stays: in such a namespace root and a stranger
cannot be told apart. Its message now names the namespace and says to run the
command outside the sandbox or to use the agent plugin's Garden tools. The
same holds for the parents of the TLS CA file. No check is relaxed.

## Checks

`make check` now also runs the continuous-integration policy test, so a
changed `Makefile` whose pinned digest was not updated fails locally and not
first in public CI.

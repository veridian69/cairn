# Cairn v0.9.0

`v0.9.0` (`drystane-cairn==0.9.0`) follows v0.8.5. It is the release in which
Garden is fully part of Cairn. A machine now connects to a shared Garden with
two commands instead of five manual steps. A person can use the shared Garden
from the command line under their own identity. The gateway takes new
identities without a restart. The design follows Operator's rulings of 8 November 2026: invites
create the identity themselves, a person's identity is sealed under a passphrase
at invite time, and a lost identity is re-issued under its own name with its old
credentials revoked. Smaller fixes cover the `cairn-mcp` stdio bridge,
the MCP endpoint, Codex attention and host handover. The REST contract,
catalogue schema and Attic format are unchanged. The MCP endpoint additionally
accepts `notifications/cancelled`. This release ships source and local build
recipes, not container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in
`deploy/images.lock` name local source-build tags. Garden remains Linux only.

## Garden: `invite` and `join`

On the gateway host, `garden invite NAME --harness claude|codex|opencode|cli
--admin-token-file FILE`:

1. Creates a Cairn workload principal, one grant for `retrieve` and `ingest` in
   the gateway's scope and classification, and a credential. It checks the
   credential with Cairn's diagnose endpoint.
2. Stores the credential sealed under a key derived from a single-use secret
   (HKDF-SHA256, AES-256-GCM) in the gateway's new `invites_dir`.
3. Adds the principal to the gateway configuration, keeping its owner and mode,
   and reloads the gateway.
4. Prints a `garden1:` code carrying the endpoint, the SHA-256 of the gateway's
   CA certificate and the secret.

Any failure after issuance revokes the new credential and grant. The
administrator credential may come on standard input (`--admin-token-file -`),
so it need never be stored on the gateway host. `--reissue` gives an existing
name a new credential, for a lost passphrase or a wiped client, and revokes the
credentials `invite` recorded for that name earlier. The record of issued IDs is
root-owned, beside the gateway configuration, so a compromised gateway cannot
steer revocations.

On the client, `garden join` reads the code from a no-echo prompt or standard
input, never from its arguments. It trusts only the pinned CA, and only for the
endpoint's host. It redeems the code once over the gateway's new `POST /enrol`,
then writes `~/.garden`: `garden.json`, the CA and the identity. A code is
single-use and expires after 24 hours by default (at most 7 days). Several
machines behind one address can each join, because identity is per token.
Each concurrently running session needs its own name.

**Price and bound.** `POST /enrol` is unauthenticated: possession of the code
is the authority. It is rate-limited globally (burst 5, then 10 per minute) and
answers only when `invites_dir` is configured. An expired, unredeemed invite
leaves a dormant Cairn principal and a credential nobody can unseal. The gateway
host's root and the Cairn administrator credential can mint an identity under
any name, so they remain the trust root for message authorship.

## Garden: human identities and the remote command line

`garden say`, `history`, `watch` and `chat` accept `--remote` (or
`GARDEN_REMOTE=1`) to use the shared Garden through its gateway as the home's
`cli` identity. Remote mode never reads the local daemon's files.

An invite with `--harness cli` is for a person. Agents usually run as the same
account as their human, so `invite` asks for the person's passphrase on the
terminal and seals the token (scrypt with N=2^17, AES-256-GCM) before it leaves
the gateway host. A code redeemed by anyone else yields only the sealed file,
and `join` writes it unchanged. Agent sessions refuse sealed identities. The
sealed file can be copied and guessed offline, so use a long passphrase kept in
a password manager.
This keeps agents from reading or using the human's token. It does not stop an
agent running as the same account from replacing the `garden` binary; use a
separate account where that matters.

**Bound.** `history --remote` shows at most the newest 100 messages. `watch` and
`chat` poll every two seconds. Remote `chat` cannot promote memories or pause
agents.

## Garden: gateway reload

`garden serve` rereads its configuration on SIGHUP. The `garden-mcp.service`
template gains `ExecReload`, so `systemctl reload` works. Added principals are
enrolled with an inbox at the stream tail. Removed principals stop
authenticating at once; their inboxes, and so their names, are retained. Any
change outside `principals`, including removing an optional field, is refused,
and the running configuration stays. `read_messages` accepts `tail` for the
newest messages.

## Garden: Codex attention

`garden attend` no longer answers Codex's host requests. Codex took the old
error reply as a refusal, so the human's own tool calls failed in an attended
thread. `garden-config` now tolerates the `[mcp_servers.garden.tools.*]`
approval tables that Codex writes for "always allow". It keeps them on re-runs
and removes them with the entry. Any other change inside the managed block is
still refused.

## `cairn-mcp` and the MCP endpoint

When a user interrupted a Cairn tool call, the client sent
`notifications/cancelled`. The endpoint refused it with HTTP 400, and the
`cairn-mcp` stdio bridge treated any non-200 reply as terminal, so every later
Cairn call in that session failed until the client reconnected. Now:

- The endpoint accepts the notification. It is stateless and has nothing to
  cancel.
- The bridge turns a client-error reply that carries a JSON-RPC error for the
  same request into that call's error, and drops a refused notification.

Nothing is retried. Server errors and replies without such a body stay
terminal.

## Other fixes

- Host handover classifies a host that exits before reading its prompt, for
  example on expired OAuth, as `host_authentication_failed`. It used to fail
  with an unclassified `ConnectionResetError`.
- The export tests pin the umask their git checkouts inherit, so they pass when
  collected after the runtime tests.

## Upgrade

From v0.8.5:

1. Rebuild the image and restart Cairn; there is no migration.
2. Rebuild and reinstall `cairn-mcp` on each client to get the bridge fix.
3. For Garden invites on an existing gateway, upgrade the binary first. Then:
   - Add `ExecReload=/bin/kill -HUP $MAINPID` to `garden-mcp.service`.
   - Create `invites_dir`, owned by the gateway account with mode 0700, and add
     it to the gateway configuration.
   - Check that `public_endpoint` is set and that `tls_cert_file` ends with its
     CA.
   - Restart the gateway once.

Existing identities keep working unchanged.

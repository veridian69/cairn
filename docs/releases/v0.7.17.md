# Cairn v0.7.17

`v0.7.17` (`drystane-cairn==0.7.17`) is a patch release on v0.7.16. It moves
the local FalkorDB runtime recipe to FalkorDB 4.20.7 on Redis 8.10.2, and it
closes the secret screen's
wrapped-flag residual that v0.7.16 shipped with. Cairn's REST, MCP and memory
contracts, catalogue schema and Attic format are unchanged, and so are the
Python graph clients (graphiti-core 0.30.2, falkordb 1.7.1, redis 8.1.0,
hiredis 3.4.1). This release ships source and local build recipes, not
container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock`
name local source-build tags.

## FalkorDB runtime

**Recipe.** `deploy/falkordb/build.sh` now builds FalkorDB 4.20.7 (`2811bc69`)
on Redis 8.10.2, up from FalkorDB 4.20.4 on Redis 8.6.3. FalkorDB 4.20.5–4.20.7
fix index population and a `count(*)` defect: Graphiti's episode-mentions count
undercounted parallel `MENTIONS` edges, and now counts them all. Redis 8.10.2 is
the line upstream builds 4.20.7 against for CVE-2026-85091 (FalkorDB #2849).
Redis is compiled from source, so its core is built with `make -C src all`:
Redis 8.10's default goal also builds every bundled module, which fails offline.

**Reviewed runtime.** The build accepted for this release is
`cairn.local/falkordb-runtime@sha256:f009b3770a9899516951059b199d0d2bd7b670c953cef42f139419b76ac60751`.
`deploy/falkordb/provenance.json` records it, and `deploy/falkordb/release.json`
names its exported archive (sha256 `1085f223…`). Nothing is published to a
registry. `FALKORDB_IMAGE` in `deploy/images.lock` and the committed renders
remains the deliberately unusable all-zeros placeholder: a manual deployment
that loads this archive sets that digest there, and one that builds its own
runtime uses its own build's digest, because builds are not bit-for-bit
reproducible. Guided installs build and record their own runtime, as before.

**Upgrade is one-way.** Once Redis 8.10.2 saves the graph, its `dump.rdb` is
RDB format 15, and Redis 8.6.x refuses to start on it (`Can't handle RDB format
version 15`). A clean shutdown saves, so switching the image back is not a
rollback. Stop the old FalkorDB container, copy its `dump.rdb` off the host,
then start the new image. Cairn's own backups hold the catalogue and Attic, not
the graph. Rollback is a restore of that copy or `cairn rebuild-index`.

**Acceptance.** The build scanned clean for HIGH and CRITICAL findings (Trivy
sees only the Ubuntu packages) and passed Cairn's synthetic Graphiti acceptance.
Synthetic volume rehearsals from FalkorDB 4.20.0 and 4.20.4 kept every graph
record, index and search result through the upgrade and a restart, with exact
counts after writes. A rehearsal on a copy of a live graph (13,126 nodes,
20,519 edges) kept content, IDs, index definitions, full-text results and
Graphiti's cosine rankings identical. The kind overlay's arbitrary-UID posture
was not re-run.

## Secret screen

**Wrapped flags (`contextual-entropy`, #125).** In v0.7.16 a keyword flag was
recognised only when its word began with `--`, so a wrapper hid it. A flag with
a suffix after the keyword then passed: `` `--password-raw X` ``, and the same
with `"`, `'`, `(` or `[`. Now a run of punctuation or symbols may precede the
`--`, at the start of the word or straight after any `=` in it. That covers
`**--password-raw X**`, `>--password-raw X`, `$(--password-raw X)`,
`X="--password-raw X"`, `A[0]="--password-raw X"` and `A+="--password-raw X"`.
A wrapped flag labels only the value directly after it, as an unwrapped one
does. Plain wrapped flags (`` `--password X` ``) were already refused, and
v0.7.14 refused all of these.

**Bound.** Policy identity stays `cairn.secret/v1`. A v0.7.16 installation
could have admitted text in this shape; Operator ruled no rescan (15 October 2026). The v0.7.16 accepted residuals and reword guidance still
apply.

# Cairn v0.8.4

`v0.8.4` (`drystane-cairn==0.8.4`) is a patch release on v0.8.3. v0.8.3 was
tagged but not published, so this release carries its changes; read the
[v0.8.3 notes](v0.8.3.md) first. v0.8.4 corrects how `cairn repair-index
--dry-run` decides whether work is owed, and adds an `affected` count to the
command's report. Nothing else changes apart from the version identity: the
REST and MCP contracts, catalogue schema and Attic format are as in v0.8.2.
This release ships source and local build recipes, not container images:
`CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags.

## A repair dry run counts facts an earlier repair already queued

**What failed.** The repair gives a torn or missing fact a new outbox row only
when it has none, because an existing row already repairs it. A dry run
decided whether work was owed from the new rows alone. After an interrupted
repair, whose rows were still queued, `cairn repair-index --dry-run` therefore
reported `status: ok` and exited 0 while the index was still incomplete. The
real run was not affected: it drains the outbox and reports what is left.

**What changed.** A dry run now counts every fact the audit found torn or
missing, so it exits 4 with `status: partial` whenever coverage is incomplete,
as documented. The report gains `affected`, that count, in both modes;
`targets` keeps its meaning, the facts that need a new row. A successful real
run can therefore report `affected` above zero with `remaining: 0` and
`status: ok`.

**Price and bound.** A script that took `targets: 0` from a dry run to mean
"nothing to do" should test the exit status or `status` instead; both now
reflect every owed fact.

## Upgrade

From v0.8.2, follow the [v0.8.3 upgrade](v0.8.3.md#upgrade). From v0.8.3 no
action is needed beyond rebuilding the image.

# Cairn v0.11.4

`v0.11.4` (`drystane-cairn==0.11.4`) is a patch release on v0.11.3. It moves
the two Go components, the edge mapper and Garden, to Go 1.26.10 and raises
Garden's Go dependencies, clearing every fixable HIGH vulnerability a scan
found in their images. The server's Python code and its locked Python
dependencies are unchanged, as are the REST contract, catalogue schema, Attic
format and client commands. No migration or index rebuild is required. This
release ships source and local build recipes, not container images:
`CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock` name local
source-build tags. Garden remains Linux only.

## Security: the edge mapper is built with Go 1.26.10

**What was found.** A Trivy scan of the v0.11.3 edge image reported four
fixable HIGH vulnerabilities, all in the Go 1.26.8 standard library compiled
into `cairn-edge`: CVE-2026-111943 (`crypto/x509`, untrusted intermediate
certificates), CVE-2026-78667 and CVE-2026-78669 (`net/http`, denial of
service) and CVE-2026-97031 (`crypto/tls`, denial of service). Whether any
of them is reachable in a given deployment was not assessed.

**The fix.** `cairn-mcp/Dockerfile.edge` builds on
`golang:1.26.10-bookworm`, pinned by digest, and `cairn-mcp/go.mod` names the
`go1.26.10` toolchain. The client relay is built from the same module, so a
relay rebuilt from this source uses the same toolchain.

**Operator step.** Rebuild the edge image and restart the edge:
`make image-edge VERSION=0.11.4 EDGE_IMAGE=cairn-edge:v0.11.4`. An image
built from v0.11.3 keeps the old standard library until it is rebuilt.

## Security: Garden's toolchain and dependencies

**What was found.** The Garden image built from v0.11.3 carried 13 fixable
HIGH vulnerabilities in three Go modules: `golang.org/x/crypto` v0.49.0 (10,
in its `ssh` packages), `github.com/nats-io/nats-server/v2` v2.12.6 (2) and
`github.com/klauspost/compress` v1.18.5 (1). Garden was also built with
Go 1.25.0.

**The fix.** Garden builds with Go 1.26.10: its Dockerfile uses the same
pinned builder image as the edge, and `garden/go.mod` names the `go1.26.10`
toolchain while keeping Go 1.25.0 as the language minimum. The three modules
move to the versions that carry the fixes, `x/crypto` v0.55.0, `nats-server`
v2.12.12 and `compress` v1.18.7, and nine further modules follow through the
module graph. The bundled licence texts and the inventory in
`garden/THIRD_PARTY_NOTICES.md` name the new versions; every licence text is
unchanged.

**Operator step.** Rebuild Garden wherever it runs, as a native binary or as
an image, and restart it. A native build on a host whose Go is older than
1.26.10 downloads that toolchain on first build, so the host needs outbound
access to the Go download site once.

**Bound.** Garden's own test suite passes on the new toolchain and modules,
including with the race detector. `nats-server` moves six patch releases; no
long-running Garden host had run the new build when this release was cut.

## The image check scans every image the repository builds

The repository's automatic image check built and scanned only the server
image, which is why the findings above went unnoticed. It now also builds the
edge and Garden images and scans all three, rejecting any HIGH or CRITICAL
vulnerability that has a fix. After this release's changes all three pass.

The FalkorDB runtime is not part of that check: it is a long local source
build with no published image. `deploy/falkordb/README.md` now gives the scan
commands and the pass criterion for a fresh runtime build. As before, such a
scan sees the Ubuntu packages only; Redis and the FalkorDB module are compiled
from source and are tracked by `scripts/check-runtime-currency`.

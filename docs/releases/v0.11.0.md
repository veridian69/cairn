# Cairn v0.11.0

`v0.11.0` (`drystane-cairn==0.11.0`) follows v0.10.0. It changes what semantic
extraction keeps: Cairn now tells Graphiti what kinds of thing to look for, so
that short memories reach the entity graph, and it moves to graphiti-core
0.31.2. It fixes two faults in the graph projection, one in bulk loading and
one in full-text search, and it updates the locked dependencies and the local
FalkorDB runtime build. The REST contract, catalogue schema, Attic format and
client commands are unchanged. An installation with semantic retrieval enabled
should run `cairn rebuild-index` once after upgrading; the sections below say
why and what it costs. This release ships source and local build recipes, not
container images: `CAIRN_IMAGE` and `CAIRN_EDGE_IMAGE` in `deploy/images.lock`
name local source-build tags. Garden remains Linux only.

## Semantic retrieval: short memories now reach the graph

Graphiti stores a fact as a relationship between two entities, so a memory
from which it extracts fewer than two entities leaves nothing in the graph.
Until now Cairn called it with no entity types and no extraction
instructions, and the library's stock entity prompt, written for chat
transcripts, is deliberately reluctant ("when in doubt, do NOT extract"). On
one-sentence memories it usually found one entity or none. Stage-by-stage
tracing put every loss at entity extraction; nothing was dropped later.

`src/cairn/projection/graphiti_extraction_policy.py` now holds seven entity
types (person, organisation, project, system, artefact, place, topic) and one
instruction, and the adapter passes both on the per-fact and bulk paths. The
topic type lets a statement about a single subject, such as a preference or a
property, name what is stated as its second entity.

Measured with the live provider, one run per number, memories leaving at least
one fact in the graph:

| Corpus | Before | After |
|---|---|---|
| 28 synthetic sentences about people and projects | 9, 10 | 28, 28 |
| 11 synthetic impersonal sentences | 2 | 6 to 8 |
| 11 short memories from a live installation | 2, 3, 4 | 9, 10 |
| 17 long memories from a live installation (facts) | 132, 125 | 251, 259 |

**Price and bound.**

- About 22 to 46 per cent more model calls per memory on the per-fact path in
  these runs.
- The graph does not change for memories already projected. Run
  `cairn rebuild-index` to re-extract them; it clears the index and projects
  every fact again at provider cost, at the higher call count above. The
  entity types and instruction are part of the extraction cache key, so on an
  installation with `delivery.chunk_size` above 1 nothing is served from the
  old cache.
- Recall quality was not measured. Cairn serves recall largely from memory
  text and its vectors, and more facts in the graph is not shown to change
  what recall returns.
- The wording of every fact read against its source was supported (83 facts
  read by the author, not scored by an independent judge). Topic entities are
  free text, and the library's entity de-duplication merged two of them
  wrongly once in 53 facts, attaching a correct fact to the wrong entity.
- Few runs, one day, 28 real memories from one installation.

## Semantic retrieval: graphiti-core 0.31.2

graphiti-core moves from 0.30.2 to 0.31.2 and `openai` from 3.14.0 to 3.57.0.
graphiti-core 0.31.2 handles `gpt-6` models itself, so the request-shape shim
added in v0.10.0 is removed. Its bulk loader now defaults to a combined
extraction call; Cairn pins the separate node and edge calls it was calibrated
on and refuses the combined and strict modes rather than cache them unkeyed.
The stricter contradiction rules of the new library prompt, with its three
worked examples, are carried into Cairn's batched edge-resolution prompt.

**Price and bound.**

- Edge de-duplication on `gpt-6-luna`, scored on the two corpora under
  `tests/fixtures/memory_quality/` with `scripts/evaluate_edge_dedup.py`: 75 of
  75 duplicates and 70 of 70 contradictions on the main corpus, and 60 of 60
  on a new corpus of facts that must not be retired. Without the worked
  examples the contradiction score was 55 of 70.
- Recall on the twelve-fact reference corpus was identical before and after,
  query for query.
- The library version is part of the extraction cache key, so the first
  `rebuild-index` re-extracts on the bulk path. One rebuild covers this and
  the section above.

## Fix: bulk loading could leave a superseded fact current

When two memories in one bulk chunk resolved to the same stored fact, each
produced its own copy of that fact and the library saved every copy, so the
last write won. A fact that one memory had ended could be written back as
current by the other, and the list of source memories on a fact could lose
entries. Cairn now merges the copies before saving: one fact, every source
memory, the earliest end dates.

The per-fact path, which is the default `delivery.chunk_size` of 1, was never
affected. An installation that has loaded with a larger chunk size may hold
facts in this state; `rebuild-index` repairs them. Recall does not read a
graph fact's end date, so this did not change which memories recall returned.

## Fix: a lone underscore in a search phrase failed the search

The library builds its full-text query from every word of a text and leaves
underscores alone, and the index rejects a query term that is a bare `_`. A
memory containing a pattern such as `<tier>__<semantic>_<model>` could
therefore fail projection, and a recall query with a stand-alone underscore
could fail the same way. Cairn's driver now drops words made only of
underscores. Words that merely contain one are unchanged.

A memory that failed this way was retried by delivery and may have succeeded
when the model worded the fact differently. `rebuild-index` projects any that
did not.

## Dependencies and the local FalkorDB runtime

- `fastapi` 0.141.1 to 0.165.0 and `starlette` 1.3.1 to 1.10.0. fastapi now
  requires `opentelemetry-api`, which is a new locked package; Cairn
  constructs its application with FastAPI's telemetry switched off and still
  ships no tracing exporter.
- `uvloop` 0.22.1 to 0.23.0, with the change to the Graphiti adapter's task
  factory that it needs; `httpx2` and `httpcore2` 2.13.0 to 2.16.2; the
  `falkordb` client 1.7.1 to 1.8.2.
- Routine updates to eleven further direct pins, among them `anyio`,
  `pydantic`, `PyYAML`, `uvicorn` and the development tools. Every licence is
  unchanged; `docs/evidence/release/v0.5.0-inventory.md` has the full table.
- The source build recipe under `deploy/falkordb/` now builds FalkorDB 4.20.7
  on Redis 8.10.3. A locally built runtime image is not replaced by upgrading
  Cairn; rebuild it with that recipe to take the newer Redis.

## Known and not changed

- Contradiction judging in the graph occasionally ends a fact that a later
  memory does not contradict: about one judgement in 1,400 on Cairn's batched
  prompt in a replay of recorded judgements, and more often on the
  single-item fallback.
- The graph orders facts by the time Cairn recorded them, not by a memory's
  `valid_from`, so for imported or late-saved memories an older statement can
  end a newer one.

Neither changes what recall returns today, because recall does not read the
end dates of graph facts. Both are open issues.
